# 研究来源选择

按用户的问题选择来源，不把下面的站点全部搜一遍。优先使用原始证据；社区与专业媒体用于补充用户体验、行业影响和不同观点。具体站点访问方式以对应的 `references/site-patterns/` 经验为准，并在使用时核对页面实际内容。

| 领域 | 核实规则、数据和原始事实 | 了解实测、体验与讨论 |
|---|---|---|
| AI、编程、API、软件与 IT | 官方技术文档、发布说明、标准、源码及 GitHub Issues/Discussions；必要时查 OpenAI Developer Community、Cursor Forum | Linux.do、V2EX、NodeSeek、Reddit、Hacker News 及对应工具论坛；关注复现步骤、版本、性能数据、故障与修复 |
| 数码、消费电子及购物 | 品牌规格、保修和支持资料；相关标准与独立测试 | V2EX、Linux.do、Reddit、酷安、小红书、知乎、品牌社区及垂直论坛；关注长期体验、缺陷、耐用性、舒适度、版本差异和价格 |
| 服装、鞋类、运动与户外装备 | 品牌尺码、材料、保修说明及专业测试 | 小红书、知乎、Reddit、日本及欧美垂直户外论坛、品牌社区；重点核对尺码、使用条件、季节和长期磨损 |
| 亚马逊及跨境电商 | 对应国家/站点的官方卖家帮助、政策公告、费用文件及税务/监管机构 | 知无不言、小红书、相关 Reddit 子版块、Amazon Seller Forums、雨果跨境及对应平台商家社区；卖家讨论的触发条件见 [亚马逊卖家讨论参考](amazon-seller-discussions.md) |
| 投资与金融 | 监管机构、交易所、上市公司公告、基金公司文件及可靠市场数据 | Reuters、Bloomberg、Financial Times、财新、Bogleheads、相关 Reddit 社区；区分数据、历史回测、预测和个人观点 |
| 旅游、徒步与交通 | 当地旅游部门、景区、交通运营商、路线管理机构及天气来源 | 小红书、Reddit、当地论坛、专业户外社区和近期游记；按目的地使用中文、英文、日文或当地语言 |
| 新闻与行业动态 | 事件相关机构公告、原始文件、财报和数据 | 国际新闻优先 Reuters、Bloomberg、Financial Times、AP；中文新闻可查财新、澎湃；科技商业可查 The Information、晚点 LatePost、36氪；跨境电商可查雨果跨境 |

## 取舍与核实

- 根据问题确定国家/地区、产品版本、事件日期及所需证据，再选最相关的官方来源和社区；以上清单是发现来源的起点，不是固定配额。
- 简单事实快速核实。复杂、争议大或需要真实案例的问题，可跨语言和来源类型检索；按问题时效设置时间范围，突发事件重点核对当天及近期内容，长期体验可扩大范围。
- 搜索摘要用于发现原文。对评论、回答或讨论进行分析时，读取相关原帖和评论；如果平台无法访问或只显示摘要，明确说明实际取得的范围，不把转载或搜索摘要冒充原帖。
- 重大争议主动寻找相反证据。多篇转述同一来源不算独立佐证；社区个案不代表总体比例，除非确有可核查统计。
- 政策、法律、税务、财报和规格问题优先追溯官方文件、公告、原始数据或源码。新闻可核实事件背景；社区可以说明执行体验，不能替代正式规则。
- 留意发布时间与事件发生时间、规则生效日、国家/站点、产品版本和卖家主体。谨慎采纳营销软文、SEO 页面及没有原始依据的转述。
- 搜索到足以支持结论的一手证据和相关独立案例，并覆盖重要分歧后即可停止；不为达到固定网页数继续重复搜索。

## 回答呈现

- 先给结论，再给支撑结论的证据、代表性体验、争议和可执行建议；按复杂程度控制篇幅。
- 比较多种方案时，优先用表格呈现性能、成本、优缺点和适用场景。
- 对重要结论链接原始讨论、官方文件或原创报道，并区分已核实事实、推测和未验证观点。
- 对时效性强的价格、政策和产品参数，说明数据日期与适用地区；不编造来源、评论、测试数据、统计比例或搜索数量。
