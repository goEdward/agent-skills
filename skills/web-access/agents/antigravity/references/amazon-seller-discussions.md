# 亚马逊卖家讨论定向检索

## 触发边界

仅用于用户明确想知道卖家群体“怎么说”、真实经历、常见故障、申诉或运营案例、争议与社区观点的任务。不要因请求中出现 Amazon、Seller Central、FBA、ASIN 等词就自动触发。

这里的“用户讨论”默认指卖家或运营者。若用户明确询问商品使用者、消费者或买家体验，不套用本路由，改按产品评论与消费者社区选择来源。

以下任务保持原有通用路径，不扩展论坛检索：

- 核实亚马逊政策、费用、资格、时限或官方流程；
- 查商品、ASIN、评论、竞品、价格或新闻；
- 用户只要官方答案或一手规则，没有要求社区经验。

讨论材料是经验性证据，不等于亚马逊政策。涉及规则或账号风险时，先用官方帮助页或公告确定事实，再用论坛补充实际案例。

## 默认来源

围绕同一个问题覆盖四个来源族，使用适合各社区的语言，而不是把同一串中文或英文机械复制到所有平台：

| 来源 | 定向范围 | 适合内容 |
|------|----------|----------|
| 知无不言 | `wearesellers.com` | 中文卖家、跨境运营、申诉与服务商生态经验；评论分析需同时读取站点经验文件 |
| 小红书 | `xiaohongshu.com` 的笔记与评论 | 中文卖家个人经历、操作记录、服务体验与近期现象 |
| Reddit | 优先 `r/AmazonSeller`、`r/FulfillmentByAmazon`；相关性不足时再扩大到 Reddit | 英文卖家案例、边缘问题、不同站点经验 |
| 亚马逊官方卖家论坛 | 当前站点对应的 `sellercentral.amazon.<站点>/seller-forums` | 卖家讨论、Amazon Employee / 社区经理回复、官方置顶说明 |

“亚马逊官方论坛”只表示平台归属；普通卖家发帖仍是社区观点。只有带 Amazon Employee、Amazon Staff、Community Manager 等明确身份标记的回复，才单独标为亚马逊人员回复。

## 检索策略

1. 从用户主题提炼一个中文核心表达和一个英文核心表达；只补充确实影响命中的产品、站点、错误码或政策名，不生成大批同义词。
2. `search_web`（或当前网页搜索工具）能可靠处理 `site:` / `OR` 时，可合并发现；否则对四个来源各做一次窄查询。环境支持并发调用时可并发，不要求顺序等待。
3. 优先保留原始帖子 URL，不用聚合页或搜索摘要代替原帖。相关结果已经足够回答时停止，不为了凑数量反复改写同类查询。
4. 知无不言、Reddit 和官方论坛在静态方式已完整取得用户所需内容时不打开浏览器。用户只需要知无不言的问题正文时可静态读取；需要回答或楼中楼评论时，直接读取 `site-patterns/wearesellers.com.md` 并使用主 skill 的外部浏览器 CDP 路径，不以回复数量代替正文。用户需要小红书原帖正文或评论时，直接读取 `site-patterns/xiaohongshu.com.md` 并用已配置的本地外部浏览器打开原帖；搜索用于发现候选，不作为已读原帖的替代。
5. 小红书在本地外部浏览器不可用或未登录时，只用公开网页搜索发现候选笔记；搜索标题或摘要不足以证明正文内容。拿不到原笔记就明确记为“小红书样本未取得”，继续其他三个来源，不阻塞整项调研，也不反复尝试登录或授权。

可用的定向起点：

```text
site:wearesellers.com <中文主题> 亚马逊
site:xiaohongshu.com/explore <中文主题> 亚马逊
site:reddit.com/r/AmazonSeller OR site:reddit.com/r/FulfillmentByAmazon <English topic>
site:sellercentral.amazon.com/seller-forums <English topic>
```

已知公开入口（截至 2026-08-20 分别验证，之后仍需以实际响应为准）：

- 知无不言的页面搜索由 `POST https://www.wearesellers.com/esearch/` 生成搜索地址，结果内容来自公开的 `/esearch/ajax/search_result_v2/?q=<中文主题>&search_type=questions&time_filter=all&page=1`；站点接口变化或结果质量差时回退网页搜索。
- 小红书搜索页 `https://www.xiaohongshu.com/search_result?keyword=<中文主题>&source=web_search_result_notes` 在无登录静态请求中通常只返回页面壳和空结果集（2026-08-20 验证），不要用 curl/Jina 反复尝试。公开搜索可能返回含 `xsec_token` 的候选 URL；这类完整地址只可在浏览器内部导航，不得发送给 Jina、写入经验文件、日志或最终答复。
- Reddit 子版块搜索可尝试公开的 `/r/<subreddit>/search.rss?q=...&restrict_sr=on&sort=relevance`；RSS 不可用时回退网页搜索或原始帖子。
- 亚马逊官方卖家论坛的讨论原帖通常可公开读取；其搜索页依赖前端时，用网页搜索定位 `seller-forums/discussions/t/` 原帖。

## 知无不言专项判断

- 搜索结果和问题正文只用于发现候选帖子。用户要求分析“评论”或“讨论”时，同时读取顶层回答和楼中楼评论；后者经常包含晚于原回答的实际处理结果或反例。
- 先记录页面显示的回复数量，再记录实际提取的顶层回答数与楼中楼评论数。三者口径不同，不应相加冒充页面回复数；数量不一致时如实说明，不为凑数重复抓取。
- 对回答者身份做来源审视：带检测认证、联系方式、服务广告或机构介绍的账号可能存在商业利益，降低其建议权重但不要自动删除；优先重视带时间、具体触发条件、提交材料和处理结果的第一手卖家案例。
- 不把“高赞”“机构身份”或大量相似服务商回复当作政策证明。社区结论与官方政策冲突时，明确保留分歧并以官方原文为规则依据。
- 不采纳隐藏真实产品属性、删除必要关键词或提交不真实材料等规避建议；这些内容可作为社区现象描述，但不能转化为操作建议。

## 汇总要求

- 至少区分“官方规则/亚马逊人员回复”和“卖家个案/观点”；不要把高赞、重复转述或多篇相似抱怨写成已证实事实。
- 保留帖子日期与站点语境；政策或界面可能已经变化，旧帖只能作为历史经验。
- 说明样本数量和分歧。只有多个独立帖子呈现相同模式时，才可描述为“多名卖家报告”；不要用“普遍”“大多数”替代未做统计的印象。
