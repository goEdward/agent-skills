# Web Access 路由规则

- 凡涉及联网研究、事实核实（含网传消息与截图真伪核查）、外部网页读取、需要登录或动态渲染的网站（如小红书、知无不言、社区评论等），或查找本人浏览器历史与书签时，**优先加载并遵循已安装的 `web-access` skill**。当用户上传截图询问“核查/真假/怎么看”且涉及现实事件时，必须先提取图中核心说法执行联网检索，严禁仅分析截图本身或在未检索时直接判“未证实”。
- 除非用户明确指定使用 Antigravity 内置浏览器，否则**不要调用内置 `browser` subagent**；需要浏览器渲染、交互或登录态时，若当前会话已加载 `browsermcp` MCP 工具则优先通过其 `browser` 工具执行（默认新建标签页并在任务结束时 `tab close` 清理）；若未安装/未加载 `browsermcp`，直接快速跳过（不做任何安装检查或配置探测），立即走 `web-access` 的本地外部浏览器 CDP 路径（使用 `~/.web-access/config.env` 中配置的浏览器与 Profile，并在任务结束时完成 `close-owned` 清理核验）；`browsermcp` 未连接或受限时亦直接回退该 CDP 路径。
- 公开且可静态完整获取的内容直接使用 `search_web` 或静态请求，不启动 CDP 检查；纯离线任务不触发 `web-access`。
- 整理联网搜索或网页读取结果时，**每条核心结论、数据、规则或案例都要在句末或条目旁直接附上对应的原始来源链接**（不要只在文末堆链接）；使用正常渲染的 Markdown 链接，**不裸露显示原始 URL 文本**，也**不加 `title` 悬停参数**（客户端会误拼进 URL）。链接文字采用**站点/论坛简称 + 极短主题词**（如「小红书·V60配方」「知无不言·申诉案例」「Reddit·FBA讨论」「官方文档·费用规则」），点击直达原文。含 `xsec_token` 等签名或凭据参数的网址先脱敏/保留规范原帖链接，并明确区分已读原文与仅搜索摘要。
